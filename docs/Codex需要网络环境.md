# Codex 工作站服务连接要求

本文件保留 UI 原型阶段确定的“网络环境”需求，并以当前源码审计后的架构为准。完整设计见 `NETWORK_AND_SERVER_CONNECTIVITY.md`。

## 设计目标

- 只让从便携工作站启动的 Codex 使用工作站服务连接。
- 不修改 Windows 系统代理、路由表或永久环境变量。
- 不影响浏览器、微信、游戏和电脑其他软件。
- 优先直接访问本产品自有 HTTPS API。
- 必要时使用只绑定 loopback、目标域名白名单化的 Connection Sidecar。
- 不提供通用 VPN、机场订阅、任意目标 SOCKS/HTTP 代理。

## 客户端检测

启动前检测：

- WebView2 Runtime。
- 移动盘 Codex 主程序。
- `CODEX_HOME`、`CODEX_SQLITE_HOME` 和 `CODEXPP_HOME`。
- 项目、插件和 SQLite 目录。
- 自有 API、设备授权和更新源。
- Connection Sidecar 完整性与本地端口。

失败项显示红色并跳转到对应配置页。已配置项不可重复点击进入首次配置流程。

## 一键启动顺序

1. 用户点击“启动 Codex”。
2. 检查移动盘和工作站状态。
3. 解锁加密凭据。
4. 获取并验证签名 route manifest。
5. 查询用户套餐或卡密权益。
6. 需要时自动启动 Connection Sidecar。
7. 生成只含 `env_key` 的 provider 配置。
8. 对子进程设置工作站环境变量。
9. 通过 Codex++ `--app-path` 启动移动盘 Codex。
10. 失败时给出真实错误，不静默修改系统网络。

## 权益逻辑

- 使用本产品模型服务套餐的用户，可以包含工作站服务连接权益。
- 使用自己 API 的用户，可以通过独立卡密获得工作站服务连接权益。
- 最终有效期由 activation-bridge 返回的服务器签名结果决定。
- 权益到期只停止新的服务连接，不删除本地项目和用户数据。

## 管理后台

管理员后台是独立服务器网址，不显示在客户端导航中。

Sub2API 已能提供中转站用户、API Key、订阅、支付、用量、并发、错误和渠道监控。工作站无需用户账号；工作站卡密、绑定数量、版本、最后在线、route manifest 和匿名环境失败统计由 activation-bridge 维护。

## 合规边界

本服务仅用于访问本产品自有且合法授权的 API。不得用于破解、攻击、非法侵入、绕过权限限制、窃取数据、传播违法信息或侵犯隐私和知识产权。

工程上的目标域名白名单、权限限制和日志策略比单纯 UI 声明更重要。正式上线前还需根据实际服务器、CDN、数据和经营模式进行法律与合规评估。
