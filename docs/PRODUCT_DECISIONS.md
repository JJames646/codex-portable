# 产品决策记录

更新时间：2026-07-16

本文件记录用户已经明确确认的产品方向。后续需求、UI、接口和开发计划必须以本文件为准；存在冲突的旧描述需要逐步清理。

## 1. 已确认的客户端路线

- 目标系统：Windows 11 x64。
- 首块测试移动存储容量：64GB。
- 正式客户端沿用 Codex++ 的 Rust + Tauri 2 + React + TypeScript 技术栈。
- 用户要的是把 Codex++ 的现有能力整合到当前“Codex 便携工作站”UI，不再保留两个相互独立的管理界面。
- Codex、Codex++ 管理能力、项目数据和工作站状态都从移动存储启动和读取。
- Codex 只允许由工作站启动台启动；不提供引导用户绕过启动台直接运行移动盘 Codex 的正式入口。
- 开发和 Windows 调试可以连接用户的 Win11 电脑。
- 用户允许在其 GitHub 账号下按工程需要创建项目；创建前仍应明确仓库用途、可见性和许可证。

## 2. 供应商与密钥导入

- 不做需要用户登录工作站账号的一键设备授权导入。
- “官方中转站”采用内置供应商预设，预设 Base URL、协议和推荐模型。
- 页面提供醒目的密钥粘贴框。
- 用户在中转站网站复制 API Key，粘贴后自动完成格式清理、供应商选择、字段填充和连接检测。
- 粘贴内容不得进入日志、URL、命令行、剪贴板历史记录或诊断包。
- 第三方供应商仍可使用完整高级表单填写 Base URL、协议、模型和 API Key。

## 3. 工作站授权与商业规则

- 工作站授权不要求注册或登录工作站账号。
- 使用卡密激活工作站服务。
- 暂定工作站产品/服务售价约为 ¥99；具体包含内容和有效期仍需确认。
- 独立工作站服务卡密暂定 ¥10；具体有效期单位仍需确认。
- 卡密有效期从第一次成功激活开始计算。
- 不支持退款。
- 一个卡密可以允许绑定多台工作站，但最大绑定数量和解绑规则必须在后台配置，不能默认无限制。
- 套餐到期后停止工作站服务连接。
- 如果当前使用本产品中转站套餐，到期后同时停止该中转站 Provider 和相关服务连接；工作站管理 UI 保持可打开，以便用户切换到自己的 API。
- 到期不得删除或锁死用户的本地项目、会话、Skills 和插件。

## 4. 无账号卡密激活

工作站安装实例以移动存储为单位生成 `installation_id` 和密钥对，不绑定某一台 Windows 电脑。

推荐流程：

```text
输入卡密
→ 客户端向 activation-bridge 提交卡密、installation_id 和公钥
→ 服务端验证卡密状态、首次激活时间和设备数量
→ 服务端返回签名 entitlement 和短期服务令牌
→ 客户端验证签名并保存到移动存储
→ 后续定期续签，不要求用户账号
```

管理员后台必须支持：

- 卡密批量生成、禁用、续期和备注。
- 首次激活时间、到期时间和剩余时间。
- 已绑定工作站列表、最后在线和客户端版本。
- 每个卡密的最大绑定数量。
- 手动解绑、封禁和重新激活。
- 工作站服务连接状态和异常统计。
- 本产品中转站套餐状态。

## 5. 首页仪表盘

- 首页主仪表盘以 Codex++ 原“概览”能力为基础，不要求用户先登录 Sub2API 网站。
- 显示 Codex 状态、便携路径、版本、项目/会话概览、供应商、插件和环境状态。
- 如果已经配置本产品中转站，可以附加显示真实用量、余额、请求量和套餐到期时间。
- “查看详情”仍可打开独立远程网站页面，但远程页面不得获得本地 Tauri 高权限。

## 6. 凭据与无 PIN 决策

- 用户明确不需要 PIN 或工作站解锁密码。
- 客户端启动后自动读取移动存储中的凭据材料。
- API Key 仍不得明文写入普通设置、日志、URL、命令行和诊断包。
- 可以使用随机生成的本地 vault key 加密凭据文件，但 vault key 同样保存在移动存储中。
- 该模式只能降低误读和普通明文泄漏风险，不能防止移动存储丢失后被有能力的人员提取密钥。
- 正式产品必须在设置和首次导入密钥时明确提示这一安全边界。

## 7. 恢复出厂设置

- 恢复出厂设置不需要账号密码。
- 必须停止 Codex、Codex++、sidecar 和更新器。
- 必须二次明确确认，并列出将删除的内容。
- 执行后删除工作站设置、卡密授权、API Key、供应商、自定义插件、Skills、会话、项目、绘画、备份和缓存，恢复为首次出厂状态。
- 操作不可撤销；正式实现应要求用户输入指定确认文字，避免误触。

## 8. 更新方式

- 每次插入并启动工作站时异步检查更新。
- 客户端检查自己的 GitHub Release 更新项目或其镜像，不直接对社区源码仓库执行 `git pull`。
- GitHub Release 中提供签名的 `stable.json`、组件压缩包、SHA-256 和版本说明。
- 更新签名私钥不能放在公开 GitHub 仓库中。
- 初期可由 GitHub Actions Secret 保存发布签名材料；正式商业发布推荐迁移到云 KMS 或离线签名机。
- 客户端只内置验签公钥。
- 更新失败继续运行旧版本，并且不得覆盖用户数据。

## 9. 许可证决策

用户已确认接受向接收者提供 Codex++ 对应修改源码，因此正式客户端继续采用 Codex++ Fork 路线。

发行要求：

- 修改后的 Codex++ 客户端整体继续遵守 `AGPL-3.0-only`。
- 每个二进制 Release 提供对应 commit/tag 的完整源码获取入口。
- 提供构建脚本、依赖锁文件、补丁记录和安装/运行所需信息。
- 保留 Codex++ 原版权、许可证和第三方声明。
- 关于页提供“开源许可证”和“对应源码”入口。
- 不得用仅提供差异补丁代替完整对应源码。
- 收费 ¥99、售卖卡密、模型额度和运营服务器服务不因此被禁止。
- activation-bridge、管理员后台和其他独立服务的许可证边界在实现时单独审查，避免与客户端形成未计划的单一派生作品。

GitHub 仓库建议已经确定为：

```text
codex-portable-workstation   公开，AGPL 客户端源码和 Codex++ Fork
codex-workstation-server     私有，activation-bridge、后台和部署配置
codex-workstation-releases   公开，签名更新清单、发行包和发行说明
```

## 10. 仍需确认

- ¥99 具体购买的是永久客户端使用权、一年服务，还是硬件和服务组合。
- ¥10 卡密的有效期是否固定为 30 天。
- 每张卡密默认允许绑定多少个移动工作站，以及是否允许用户自助解绑。
- 首页需要保留哪些 Codex++ 概览指标。
- 本产品中转站套餐到期时，是否立即关闭正在运行的 Codex，还是仅阻止新的模型请求并提示切换供应商。
